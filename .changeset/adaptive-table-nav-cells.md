Adaptive table and app-nav geometry. The Table component's narrow-width contract is now shipped, not just documented: `renderTable` labels every body and footer cell by default (`labelCells` defaults to true, stamping `srLabel` where a column has no visible label), the `[data-bn="table-container"]` wrapper is a named container, and `states.css` restacks the table against its own width under `@container table (max-width: 40rem)` — each row a block, each cell a line headed by its `data-label`, long unbroken content wrapping instead of clipping. A table that opted out (`labelCells: false`) keeps the container's horizontal scroll. In the app nav, the More button renders inside the list in a cell of its own (`app-nav-more-cell`), so the bar's cells are equal width and its edge insets symmetric — as a content-sized flex child of the `<nav>` it measured 45.6px against 85.4px destination cells. Bar links lose their inline padding (the cell is the hit area) and labels can no longer unbalance a cell: cells carry `min-inline-size: 0` and a label ellipsises only when it truly cannot fit. Layout regression coverage for both contracts lives in `tests/e2e/adaptive.spec.js`, asserting rendered geometry (text rects inside cell boxes, cell widths, insets) rather than markup alone.
