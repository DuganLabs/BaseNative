The app

The catalog's one end-to-end demo: a real task manager, rendered on the server and hydrated in the browser. The list above the controls is the server render; the controls drive the same list through signals.

How it works

The server renders the current list into the page — the count and the rows are real HTML before any script runs. The browser then hydrates that markup with signal, computed and effect from @basenative/runtime: the filter, the summary line and the counts are derived values, and the server-rendered list stays in sync through the same signal.

On the dev server the app talks to /api/tasks — POST to add, DELETE to remove — the site's one API. The static build has no API, so there the list is kept in your browser's localStorage instead; the notice under the title says so when that is the case.

The pieces are the catalog's own: the server-rendered list is the list group, each status rides as a badge, and the actions are native buttons.
