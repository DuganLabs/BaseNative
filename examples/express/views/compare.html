Templates are data

BaseNative expressions are interpreted by a hand-written parser — a tokenizer, a recursive-descent grammar, a scope object. There is no eval and no Function constructor anywhere in the shipped runtime or server; the count is taken from source on every build, and it is {{ stats.unsafeEvalUses }}. A BaseNative page runs under script-src 'self' with no 'unsafe-eval' — and unlike the compiled frameworks, that does not depend on a build having happened first.

Because a template is never compiled into code, a template is data. It can live in a CMS, come out of a database, or be written by a model, and rendering it cannot turn it into an injection: the parser interprets a deliberate subset — property access, calls into the provided scope, operators, ternaries — and blocklists prototype access. React, Angular and Svelte are safe the opposite way: their templates become code at build time, which is exactly why a template has to go through the build before it can run at all.

Honest tradeoffs

BaseNative isn't trying to replace React or Angular for every use case. Here's where it genuinely excels and where you should think twice.

Where BaseNative wins

  • Zero build, zero core deps — ship an HTML file
  • The reactivity core is {{ stats.coreLines }} lines; the whole runtime is {{ stats.runtimeSourceLines }}
  • {{ stats.hydrationStrategies }} built-in lazy hydration strategies
  • CSP-safe without compilation
  • Valid HTML templates that work without JS
  • {{ stats.smallerThanReact }}× smaller than React, {{ stats.smallerThanAngular }}× smaller than Angular
  • No lock-in: the component model is semantic HTML itself — walk away and your markup is still just HTML

Where others win

  • The component model is the platform itself — semantic HTML composed as native DOM, with no framework component layer (or component library ecosystem) on top
  • Ecosystem of one — no third-party component libs
  • Runtime expression parsing has overhead vs compiled output
  • Svelte has the better-polished DX and the mature compiler toolchain
  • No React DevTools, no Angular CLI, no Svelte inspector
  • Solo-maintained — bus factor of one
  • Almost nobody has heard of it — hiring and onboarding start from zero

When to choose BaseNative

Good fit

  • Content sites that need light interactivity
  • Projects where you want to own every line
  • Edge-deployed apps on Cloudflare Workers
  • Teams tired of build tool churn
  • Prototypes that need to ship in minutes
  • Embedded widgets in existing pages

Probably not

  • Large team apps that need enforced architecture
  • Projects requiring deep third-party integrations
  • Apps where a mature devtools inspector is critical workflow
  • Enterprise apps with strict hiring pool requirements
  • Complex SPAs with hundreds of components
