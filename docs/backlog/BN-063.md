## What the user hits

Every hour label in the calendar's time gutter sits one row lower than the hour it names, so on the default 7am–7pm grid the "6pm" label prints on top of the 5pm band and the last two hours look like one. The top band of the grid has no drop target at all, so dragging a job onto the first visible hour does nothing — the block snaps back with no message and no change — while a drop anywhere in the bottom band lands on the wrong hour. The calendar looks approximately right, which is why this reads as "the times are off by one" rather than as a bug.

## Why it happens

Labels and slots both number their rows as if they were children of the outer calendar grid, where row 1 is the day-header row:

- `packages/components/src/calendar.js:259` — labels: `style="grid-row: ${h - hourStart + 2}"`
- `packages/components/src/calendar.js:284` — slots: `style="grid-row: ${h - hourStart + 2}"`
- `packages/components/src/calendar.js:266` — events: `const topRow = Math.max(from - hourStart + 2, 2);`

But neither parent is a child of that grid's row axis in the way the `+2` assumes — both are **subgrids** spanning the outer grid's rows 2 through the end:

- `packages/components/src/components.css:1509-1515` — `[data-bn="calendar-time-gutter"] { grid-column: 1; grid-row: 2 / -1; display: grid; grid-template-rows: subgrid; }`
- `packages/components/src/components.css:1524-1530` — `[data-bn="calendar-day-column"] { position: relative; display: grid; grid-row: 2 / -1; grid-template-rows: subgrid; }`

The outer grid is `grid-template-rows: auto repeat(var(--bn-calendar-hours, 12), minmax(3.5rem, 1fr))` (`components.css:1484`), so outer row 1 is the header and outer rows 2..N+1 are the hours. A subgrid spanning outer rows `2 / -1` re-bases its line numbering: its **local row 1 already is the first hour row**. Every label, slot and event therefore lands one row too low, and the last one — local row `totalHours + 1` — falls past the subgrid's explicit tracks and is clamped back onto the final track, stacking hour `hourEnd - 1` on top of hour `hourEnd - 2`. Local row 1 gets no slot at all, so a drag released over the top band finds no `[data-bn="calendar-slot"]`, the `dragover` handler at `packages/components/src/calendar.js:453-460` never calls `preventDefault()`, and the drop is refused silently.

The regression test at `packages/components/src/components.test.js:955-972` does not catch it: it asserts only that the label, slot and event for 11am **share** a row (`components.test.js:970-971`), which they do — all three carry the same `+2` — so it passes while all three are wrong together.

## The fix

Change the offset from `+2` to `+1` in all three emissions, and fix the comment that justifies the wrong convention.

1. `packages/components/src/calendar.js:259` — labels: `style="grid-row: ${h - hourStart + 1}"`.
2. `packages/components/src/calendar.js:284` — slots: `style="grid-row: ${h - hourStart + 1}"`.
3. `packages/components/src/calendar.js:266` — events: the row start becomes `firstRow + 1` where `firstRow = Math.floor(startOffset)` is 0-based. This is exactly the expression **BN-010** rewrites; implement BN-010's step 1 and this step as one edit rather than shifting the line twice.
4. Rewrite the comment at `packages/components/src/calendar.js:250-254`. It currently states "Row 1 of the grid is the day-header row … so hour rows start at row 2", which is true of the outer grid and false of the subgrid these children actually live in. Replace it with: the gutter and day columns are subgrids spanning outer rows `2 / -1`, so their local row 1 *is* the first hour row and hour `h` is local row `h - hourStart + 1`.
5. Strengthen the alignment test so the numbering itself is asserted, not just agreement — see below. Chosen over asserting computed layout because these are string-rendering functions and the suite has no browser.
6. Update the rendered-markup sample in `docs/api/components.md:982-985`, which shows `style="grid-row: 2"` for the 7am label and slot and `style="grid-row: 4 / span 2;"` for an event.

## How we will know it worked

Extend the existing test `'aligns the hour label, slot, and event to the same grid row'` at `packages/components/src/components.test.js:955-972` with absolute-row assertions, so agreement on a wrong number can no longer pass:

```js
// hours: { start: 9, end: 17 }; 11am is the third hour → subgrid-local row 3
assert.equal(labelMatch[1], '3', '11am is the third hour row of the subgrid');
```

and add a boundary test that the current code cannot satisfy:

```js
it('gives the first and last hour their own subgrid rows', () => {
  const html = renderCalendar({ startDate: '2025-06-02', hours: { start: 7, end: 19 } });
  assert.match(html, /data-bn="calendar-time-label" data-hour="7" style="grid-row: 1"/);
  assert.match(html, /data-bn="calendar-time-label" data-hour="18" style="grid-row: 12"/);
  assert.match(html, /data-bn="calendar-slot" data-date="2025-06-02" data-hour="7" style="grid-row: 1"/);
  assert.match(html, /data-bn="calendar-slot" data-date="2025-06-02" data-hour="18" style="grid-row: 12"/);
});
```

Before the change this fails (it emits rows 2 and 13 against a 12-track subgrid); after, it passes. Run `cd packages/components && node --test`.

Every event `grid-row` assertion in the suite shifts down by one: `components.test.js` lines **2235, 2245, 2518, 2525, 2530, 2563, 2618, 2637, 2655, 2656, 2657, 2666, 2675**. (Line 2483 is `renderLayoutGrid`, not the calendar — leave it.)

One thing no test can see: open `/components/calendar` on the example site and confirm the "7pm"/"6pm" labels no longer overprint and that a drag released on the topmost band now highlights a slot and completes. The overprint is a rendered-layout fact.

## Notes

- **Same root cause and same lines as BN-010.** BN-010 replaces the event row expression to stop emitting a fractional `grid-row` start; this ticket corrects the constant in that same expression plus the two loops. Do them in one commit — landing either alone means editing the same thirteen test assertions twice. BN-010 is the more severe half (a fractional row makes a block cover the whole column); this half is a one-hour visual shift plus a dead top band.
- Do **not** "fix" this by removing `grid-template-rows: subgrid` from the gutter and day column. The subgrid is what keeps the hour bands in the gutter aligned with the hour bands in all seven day columns; drop it and the two axes drift apart the moment any column's content changes its intrinsic height.
- `[data-bn="calendar-day-header"]` is `grid-row: 1` (`components.css:1495`) and `[data-bn="calendar-corner"]` is `grid-row: 1` (`components.css:1489`) — those *are* direct children of the outer grid and are already correct. Do not shift them.
