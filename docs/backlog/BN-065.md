## What the user hits

`/roadmap` shows a readiness tile reading **Public Packages 39**. The workspace publishes 42.
Nobody is harmed by this today, but it is a number on the page a reader uses to judge how real
the project is, and it undercounts by three — so the page makes BaseNative look smaller than it
is, and it will keep drifting further with every package added.

## Why it happens

It is a string literal, not a derived value. `examples/express/site-data.js:92`, inside
`getRoadmapPageContext()` (`examples/express/site-data.js:87`):

```js
      { label: 'Public Packages', value: '39' },
```

The arithmetic on current main: `ls -d packages/*/ | wc -l` = 45, and
`grep -l '"private": true' packages/*/package.json` returns three —
`packages/evals/package.json`, `packages/fonts/package.json`, `packages/icons/package.json`.
45 − 3 = **42** publishable `@basenative/*` packages.

The gap is actively widening: `@basenative/theme` was added this week (commit `294e449` —
`packages/theme/src/bridge.css`, `bridge.js`, `theme.test.js` are all present) and the literal
did not move.

The machinery to derive it already exists and is already imported by this very file.
`scripts/compare-stats.js:119-128`:

```js
function workspacePackages() {
  return readdirSync(join(root, 'packages'))
    .map((dir) => {
      try {
        return { dir, pkg: readJson('packages', dir, 'package.json') };
      } catch {
        return null;
      }
    })
    .filter(Boolean);
```

and `examples/express/site-data.js:3` already does
`import { computeCompareStats } from '../../scripts/compare-stats.js';`.

Why it survived: `/compare` is guarded against exactly this class of drift —
`checkComparePage()` (`scripts/check-compare-page.js:37`) refuses to build a `/compare` whose
numbers disagree with the source, called from `scripts/build-pages.js:67` and asserted in
`tests/integration/integration.test.js:335`. `/roadmap` has no equivalent guard, so the same
kind of claim on a different page rots unchecked.

## The fix

Derive it. Do not retype `42` — a corrected literal is the same bug with a fresher value, and
CLAUDE.md is explicit about this pattern under Key Invariants: *"Do not re-type this number
anywhere"*.

1. **Export a package count from `scripts/compare-stats.js`.** Add it to the object
   `computeCompareStats()` returns, computed as
   `workspacePackages().filter(({ pkg }) => !pkg.private).length` using the existing
   `workspacePackages()` helper at `scripts/compare-stats.js:119`. Filter on `pkg.private`
   rather than counting directories minus a hardcoded three, so a newly-privated package is
   handled without an edit.
2. **Read it in `getRoadmapPageContext()`.** Replace the literal at
   `examples/express/site-data.js:92` with `String(compareStats.publicPackages)` (or whatever
   the field is named in step 1), reusing the module's existing cached `computeCompareStats()`
   result — the comment at `examples/express/site-data.js:18-20` notes the derivation is
   expensive because it bundles the runtime with esbuild, and that both the home page and
   `/compare` deliberately read through one cache. The accessor is
   `const stats = () => (compareStats ??= computeCompareStats());` at
   `examples/express/site-data.js:22` — call `stats()`, and do not add a second
   `computeCompareStats()` call.
3. **Extend the guard to `/roadmap`.** In `scripts/check-compare-page.js`, generalise the
   rendered-claim check so it also renders the `/roadmap` route and asserts the readiness tile
   values are not literals in `examples/express/site-data.js`. Prefer extending
   `checkComparePage()` (renaming it if you like) over writing a second script: it is already
   wired into both the build (`scripts/build-pages.js:67`) and the PR test suite
   (`tests/integration/integration.test.js:335`), so one change gets both enforcement points.
4. **Audit the other three readiness tiles while you are in there** —
   `examples/express/site-data.js:89-93` also hardcodes `'v0.4+'`, `'4 engines'` and
   `'Shipped'`. The milestone and browser count are plausible candidates for the same
   treatment; `'Shipped'` is a judgement, not a measurement, and should stay a literal. Do not
   silently leave the other three unexamined.

## How we will know it worked

The test fails before and passes after, in the suite that already owns this kind of assertion.
Add to `tests/integration/integration.test.js` beside
`§ 12. /compare: published claims match the source`
(`tests/integration/integration.test.js:331-340`):

```js
import { readdirSync, readFileSync } from 'node:fs';
import { getRoadmapPageContext } from '../../examples/express/site-data.js';

const expected = readdirSync('packages').filter((d) => {
  try { return !JSON.parse(readFileSync(`packages/${d}/package.json`, 'utf8')).private; }
  catch { return false; }
}).length;

const tile = getRoadmapPageContext().readinessStats.find((s) => s.label === 'Public Packages');
assert.equal(Number(tile.value), expected);
```

Today that asserts `39 === 42` and fails. Note it recomputes the count independently rather
than importing the same helper the fix uses — an assertion that calls the code under test to
produce its own expectation proves nothing (the memory note "Tests stub their own contracts"
is the general case).

Also confirm the source-literal half: `grep -n "value: '[0-9]" examples/express/site-data.js`
should return nothing after the change.

## Notes

- Root cause shared with BN-057, BN-058 and BN-061: a page states a fact about the repo and
  nothing checks it. `/compare` is the only page with a guard. BN-058 asks for the same guard
  extension for a *capability* claim ("No HMR") rather than a number. If both are worked
  together, extend `scripts/check-compare-page.js` once with both claim kinds — but neither
  ticket blocks the other, and this one is a one-line derivation plus a test.
- **Do not hand-edit `docs/package-inventory.md` to reconcile the count.** It is generated by
  `scripts/package-inventory.js` and CI fails on drift (CLAUDE.md § Precedence). Same for
  `llms.txt` / `llms-full.txt` (`scripts/llms-txt.js`). If the inventory disagrees with your
  count, regenerate it and investigate the difference rather than editing either side.
- CLAUDE.md itself carries counts that will disagree with 42: the workspace-structure comment
  says *"43 @basenative/* packages (3 private: fonts, evals, icons)"*
  (`CLAUDE.md:27`) and the registry note says *"40 in sync, 3 private as of 2026-09-11"*. The
  file's own guidance is to re-check `docs/package-inventory.md` rather than trust those
  numbers. Updating CLAUDE.md is optional and out of this ticket's scope; if you do, note that
  the same "don't retype it" argument applies and it is documentation rather than a rendered
  claim.
- 45 directories includes `packages/marketplace` and `packages/visual-builder`, which are real
  publishable packages despite being infrastructure — do not exclude them on a judgement call.
  The only exclusion criterion is `"private": true`.
