## What the user hits

Someone evaluating BaseNative reads the component catalogue, sees "fuzzy filter", "arrow-key navigation", "expand/collapse", "chip removal and keyboard support", "only renders the visible slice", tries each one on its demo page, and finds that none of them do anything. The command palette prints "↑↓ Navigate / ↵ Select" in its own footer and responds to neither key; typing in its search box filters nothing. Tree disclosure triangles do not expand. Multiselect chips have × buttons that never remove anything. The data grid's column headers look sortable and never sort. The virtual list renders a fixed first window and never changes as you scroll. Even the tabs — which *do* have a complete keyboard implementation in the package — are arrow-key-dead on every demo page. The impression is a library whose docs describe a product that was never built, which is worse for adoption than a smaller honest one.

## Why it happens

The package exports exactly three client initialisers plus the toast queue. In `packages/components/src/index.js`: `initTabs` (line 71) and `initCalendarDragDrop` / `initPipelineDragDrop` (line 92), plus `createToaster` / `showToast` / `dismissToast` (line 29). There is no `initCommandPalette`, `initDataGrid`, `initTree`, `initMultiselect`, `initDropdownMenu`, or `initVirtualList`. The example site ships none either: `grep -o 'init[A-Za-z]*' examples/express/public/basenative.js` returns only the word `initial`.

Advertised versus shipped, each verified:

| Catalogue claim | Where | Shipped reality |
| --- | --- | --- |
| "Modal dialog with grouped commands, fuzzy filter, and shortcuts" | `examples/express/component-catalog.js:413` | `command-palette.js:53` renders an input with no handler; no filter, no arrow handling, no Ctrl+K — while `command-palette.js:57-58` prints "↑↓ Navigate" and "↵ Select" |
| "Sortable, selectable grid built on native table with arrow-key navigation" | `component-catalog.js:462` | `datagrid.js:69-71` wraps a sortable label in a real `<button>` but no click handler sorts; `datagrid.js:75-77` renders a select-all checkbox with no handler; no arrow-key navigation anywhere |
| `role="tree"` list with "expand/collapse and selection state" | `component-catalog.js:497` | `tree.js:57` renders the toggle `<button>` with no handler; six of seven nodes keep `tabindex="-1"` via `rovingTabIndex` (`tree.js:47`) and nothing moves it |
| "Tag-based multi-value select with chip removal and keyboard support" | `component-catalog.js:195` | `multiselect.js:44` renders the `tag-remove` button and `multiselect.js:59` the search input; neither has a handler anywhere |
| "Windowed list — only renders the visible slice for long collections" | `component-catalog.js:524` | `virtualizer.js:41` slices `items.slice(0, visibleCount)` once at render; nothing re-windows on scroll |
| "Popover-anchored menu with keyboard navigation and shortcuts" | `component-catalog.js:579` | `dropdown-menu.js:40` gets open/Esc/light-dismiss free from the Popover API, but there is no arrow-key navigation between items and the menu does not close on select |
| "Tablist with arrow-key navigation and proper ARIA wiring" | `component-catalog.js:342` | The package *does* ship this — `initTabs` at `tabs.js:80` implements the full APG pattern including the roving tabindex (`tabs.js:92-94`). The site never calls it: `examples/express/component-demo-scripts.js:296-305` hand-rolls a click-only handler that flips `aria-selected` and `hidden` and ignores `tabindex` entirely, so tabs 2–3 stay at `tabindex="-1"` and the arrows are dead on every `/components/*` page |

Three of the audit's original claims are already **closed** and must not be re-opened:

- Tooltip now splices the popover attributes onto a real `<button>`/`<input>` invoker (`tooltip.js:15` `INVOKER_TAG_RE`, `tooltip.js:54-57`), so it opens by click and by keyboard. The only wrong part left is the demo's label "Hover or focus me" at `examples/express/component-demos.js:1147` — it does not open on hover.
- Dropdown menu gets open / Esc / light-dismiss from the Popover API (`dropdown-menu.js:40-41`); only the intra-menu arrow keys are missing.
- Data grid (`datagrid.js:15-19`) and tree (`tree.js:15-22`) now state plainly in their doc comments that wiring the click, and moving the roving tabindex, is the caller's job. The *code* is honest; the *catalogue* is not.

## The fix

**This ticket needs a decision before it can be executed** (see `decision` in the frontmatter). Two coherent answers, and the work differs completely:

**Option A — ship the interaction.** Add one small initialiser per component in the same shape as `initTabs` (`tabs.js:80`: takes a root element and an options object, re-queries on every interaction, returns `{ …imperative methods, destroy() }`):

1. `initCommandPalette(dialog, { onSelect })` — substring filter over `[data-bn="command-item"]` on input, ArrowUp/ArrowDown roving `aria-activedescendant`, Enter to activate, and an optional `hotkey: 'Mod+K'` that calls `showModal()`.
2. `initDataGrid(wrapper, { onSort, onSelectionChange })` — click on `[data-bn="datagrid-th-button"]` (`datagrid.js:70`) emits `{ key, dir }`; the select-all checkbox (`datagrid.js:76`) toggles the row checkboxes; grid-pattern arrow-key navigation across cells.
3. `initTree(ul, { onToggle, onSelect })` — click on `[data-bn="tree-toggle"]` (`tree.js:57`) flips `aria-expanded` and shows/hides the child `<ul data-bn="tree-children">` (`tree.js:66`); Arrow keys move the roving `tabindex` set by `rovingTabIndex` (`tree.js:47`) per the APG tree pattern.
4. `initMultiselect(root, { onChange })` — `[data-bn="tag-remove"]` (`multiselect.js:44`) deselects in the hidden `<select multiple>` (`multiselect.js:61`), which stays the source of truth; the search input (`multiselect.js:59`) filters and Backspace on an empty input removes the last chip.
5. `initVirtualList(container, { items, renderItem })` — re-slice on `scroll` using the `data-item-height` and `data-total` already emitted on `[data-bn="virtual-window"]` (`virtualizer.js:56`) and reposition the window via its `top`.
6. `initDropdownMenu(root)` — Arrow/Home/End between `[data-bn="dropdown-item"]` (`dropdown-menu.js:35`) and `hidePopover()` on activation.
7. Export each from `packages/components/src/index.js` next to its `render*`, and add them to the example site bundle so `grep -o 'init[A-Za-z]*' examples/express/public/basenative.js` stops returning nothing.

**Option B — stay markup-only.** Leave the package as pure renderers and rewrite every claim listed in the table above in `examples/express/component-catalog.js` (lines 195, 342, 413, 462, 497, 524, 579) to promise only what the markup delivers, following the honest wording `datagrid.js:15-19` and `tree.js:15-22` already use. Then delete the lie the markup itself tells: the "↑↓ Navigate / ↵ Select" footer at `command-palette.js:56-60`.

**These four items are true under either option and should land regardless — do them now, do not block them on the decision:**

1. Replace the hand-rolled tab handler at `examples/express/component-demo-scripts.js:296-305` with a call to the package's `initTabs`. The implementation already exists and is already correct; the site simply is not using it. This is the single highest-value line-count-to-credibility change here.
2. Change the tooltip demo title/label at `examples/express/component-demos.js:1144` ("Hover for context") and `:1147` ("Hover or focus me") to say click or focus — the Popover API invoker opens on activation, not hover.
3. Under Option B, remove the command palette's footer hint; under Option A, implement the keys it names. Either way `command-palette.js:57-58` must stop claiming keys that do nothing.
4. Whatever is decided, make `docs/api/components.md` and `examples/express/component-catalog.js` agree with each other and with the doc comments in the source files.

Recommendation if nobody is available to decide: **Option A for tree, multiselect and command palette** (their markup is inert without a client — the toggle button, the × and the filter input have no non-JS meaning, exactly the argument BN-019 makes for the drawer) and **Option B for the data grid and virtual list** (a server-rendered sort link and a server-paged list are legitimate zero-JS designs that the current markup already supports). Do not adopt that split without the owner's sign-off; it is a recommendation, not the decision.

## How we will know it worked

Under **Option A**, one test per new initialiser in `packages/components/src/components.test.js`, driven by the same hand-rolled element/event stub the `initCalendarDragDrop` and `initTabs` tests already use (CLAUDE.md pins the suite to the Node built-in runner — `cd packages/components && node --test`; no Jest, no Vitest, and no DOM library dependency). The shape that fails before and passes after, for each:

```js
it('filters the command list as you type', () => {
  const palette = initCommandPalette(dialogStub, {});
  fire(input, 'input', { target: { value: 'set' } });
  assert.equal(visibleItems().map(i => i.textContent), ['Settings']);
});
```

Under **Option B**, the test is a consistency check rather than a behaviour test — add one to the example site's test suite that asserts no catalogue `summary` string contains a capability verb the package does not ship:

```js
const FORBIDDEN = [/arrow-key/i, /fuzzy filter/i, /expand\/collapse/i, /chip removal/i, /only renders the visible slice/i];
// allowed only for entries whose component has a shipped init* export
```

That one is worth writing either way: it is what would have caught this drift in the first place, and it fails today on seven catalogue entries.

For the four unconditional items, the check on item 1 is a test — assert that `component-demo-scripts.js`'s shared script references `initTabs` and no longer sets `aria-selected` by hand. Items 2–4 are copy and cannot be tested: open `/components/tooltip` and confirm the label matches the behaviour, and open `/components/command-palette` and confirm the footer matches the keys that work.

## Notes

- **Audit status is "partially fixed", not "open".** Tooltip invoker semantics, the data grid's header `<button>`, the data grid and tree doc comments, and dropdown open/Esc/light-dismiss all landed after the original finding and are listed above as closed. Re-verify them before reworking anything in those files so the fix does not regress work already done.
- **Related to BN-019** (drawer), which is the same drift — markup that documents a client contract nobody ships. BN-019 is `decision_needed: false` because `renderDrawer` emits `inert`, which makes its markup actively broken without a client rather than merely static; the components here degrade to static, which is why this one is a real choice. Whatever is decided here should be applied to the drawer consistently, but do not block BN-019 on this ticket.
- **Do not "fix" the tabs problem by improving the hand-rolled handler** at `component-demo-scripts.js:296-305`. `initTabs` (`tabs.js:80-130+`) already implements automatic/manual activation, wrapping, disabled-tab skipping, the roving tabindex, and `onChange`. Duplicating any of that on the site is how the two drifted apart.
- The example site's demo pages get their JavaScript from `examples/express/component-demo-scripts.js` (per-slug scripts plus a `sharedScript`) — that is the file to change for site behaviour, not the demo HTML in `examples/express/component-demos.js`.
- CLAUDE.md, "Constitution": semantic HTML only, no namespace theater, zero inline styles. Any initialiser added under Option A must work off the existing `data-bn="…"` hooks and native ARIA attributes and must not introduce custom elements or inline style writes.
